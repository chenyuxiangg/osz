## 内部接口

Shell模块的内部接口（以`STATIC`关键字定义的函数）实现了Shell的核心功能，包括初始化、缓冲区管理、历史命令管理、特殊键处理和状态机处理等。这些接口不对外暴露，仅在模块内部使用。

### 初始化相关函数

#### `inner_shell_task_create(VOID)`
- **作用**：创建Shell任务，分配任务栈并设置任务参数。该函数在Shell初始化时被调用，负责创建独立的Shell任务线程。
- **限制**：
  - 需要内存管理模块支持动态内存分配
  - 任务栈大小为0x800字节，固定不可配置
  - 任务优先级固定为0x9
- **使用流程**：
  1. 调用`osz_malloc()`分配任务栈内存
  2. 配置任务参数（名称、栈属性、栈基址、栈大小、优先级、线程函数）
  3. 调用`osz_create_task()`创建任务
  4. 调用`osz_task_resume()`恢复任务执行
  5. 如果创建失败，释放已分配的任务栈内存

#### `inner_shell_register_system_cmd(VOID)`
- **作用**：注册系统静态命令。遍历链接器定义的静态命令段(`.osz_cmd`)，将其中所有静态注册的命令添加到命令链表中。
- **限制**：
  - 依赖链接器符号`__cmd_start`和`__cmd_end`
  - 只能注册编译期静态定义的命令
- **使用流程**：
  1. 从`g_cmd_start`到`g_cmd_end`遍历静态命令段
  2. 对每个`CMD_PARAMS`结构体，调用`shell_register_cmd()`注册命令
  3. 地址按`sizeof(CMD_PARAMS)`递增，确保正确遍历

#### `inner_shell_init(VOID)`
- **作用**：Shell模块初始化函数。初始化所有全局变量和数据结构，创建Shell任务，注册系统命令。
- **限制**：
  - 通过`MODULE_INIT()`宏注册为L4级别初始化函数
  - 必须在系统启动早期调用，确保Shell功能可用
- **使用流程**：
  1. 初始化命令链表头`g_cmd_head`
  2. 清零历史命令缓冲区`g_shell_history`
  3. 清零Shell控制块缓冲区`g_shell_cb.buf`
  4. 设置Shell控制块初始状态
  5. 创建FIFO队列用于输入缓冲
  6. 调用`inner_shell_task_create()`创建Shell任务
  7. 调用`inner_shell_register_system_cmd()`注册系统命令

### 缓冲区管理函数

#### `inner_shell_buf_is_full()`
- **作用**：检查输入缓冲区是否已满。比较当前缓冲区大小`buf_cur_size`与缓冲区容量`shell_capcity`。
- **限制**：
  - 缓冲区容量固定为`SHELL_BUFFER_MAX_NUM - 1`（1023字节）
  - 仅检查缓冲区大小，不处理其他错误情况
- **使用流程**：
  1. 比较`g_shell_cb.buf_cur_size`和`g_shell_cb.shell_capcity`
  2. 返回`TRUE`表示缓冲区已满，`FALSE`表示未满
  3. 在`inner_shell_deal_get_phase()`中调用，防止缓冲区溢出

#### `inner_shell_char_is_special(CHAR c)`
- **作用**：判断字符是否为特殊字符。特殊字符包括删除键、Tab键、回车键、ESC键和左方括号键。
- **限制**：
  - 仅识别预定义的几个特殊字符
  - 不支持自定义特殊字符扩展
- **使用流程**：
  1. 检查字符`c`是否等于预定义的特殊字符常量
  2. 返回`TRUE`表示是特殊字符，`FALSE`表示是普通字符
  3. 在`inner_shell_deal_get_phase()`中调用，用于区分普通字符和特殊字符处理

#### `inner_shell_buf_cursor_has_shifted(VOID)`
- **作用**：检查缓冲区光标是否已偏移。比较当前光标位置`shell_buf_cursor`与缓冲区末尾位置。
- **限制**：
  - 仅检查光标是否在缓冲区中间位置
  - 不验证光标位置的合法性
- **使用流程**：
  1. 比较`g_shell_cb.shell_buf_cursor`和`(g_shell_cb.buf + g_shell_cb.buf_cur_size)`
  2. 返回`TRUE`表示光标已偏移（不在末尾），`FALSE`表示光标在末尾
  3. 在`inner_shell_deal_get_phase()`中调用，用于确定是否需要重排缓冲区内容

#### `inner_shell_reprint_with_cursor_shift(UINT32 gap_size)`
- **作用**：在光标偏移时重新打印缓冲区内容。当在缓冲区中间插入字符时，需要重新显示后续字符并移动光标回正确位置。
- **限制**：
  - 需要准确的`gap_size`参数（光标后字符数量）
  - 依赖`SHELL_PRINT`宏输出字符
- **使用流程**：
  1. 打印从光标位置开始的缓冲区内容
  2. 根据`gap_size`移动光标回正确位置（使用退格符）
  3. 在`inner_shell_deal_get_phase()`中调用，当光标不在末尾时插入字符

#### `inner_shell_change_space_to_zero(VOID)`
- **作用**：将缓冲区中的空格字符替换为字符串结束符`\0`。用于命令参数解析，将命令字符串分割为多个参数。
- **限制**：
  - 会修改原始缓冲区内容
  - 仅处理空格字符（0x20），不处理其他空白字符
- **使用流程**：
  1. 遍历缓冲区中的每个字符
  2. 将遇到的空格字符替换为`\0`
  3. 在`inner_shell_deal_parse_phase()`中调用，为参数解析做准备

#### `inner_shell_reset_shellcb_buf(VOID)`
- **作用**：重置Shell控制块缓冲区。清空缓冲区内容，重置光标位置和缓冲区大小。
- **限制**：
  - 仅重置缓冲区相关字段，不重置其他状态
- **使用流程**：
  1. 使用`memset()`清空缓冲区
  2. 重置光标指针到缓冲区起始位置
  3. 重置缓冲区大小为0
  4. 在历史命令导航和错误处理中调用

### 历史命令管理函数

#### `inner_shell_record_history_cmd(VOID)`
- **作用**：将当前缓冲区中的命令记录到历史命令中。支持去重机制，避免连续相同命令重复记录。
- **限制**：
  - 历史命令数量受`OSZ_CFG_SHELL_HISTORY_CMD_NUM`限制
  - 空命令（长度为0）不会被记录
- **使用流程**：
  1. 检查命令是否为空，为空则直接返回
  2. 检查是否与上一条历史命令相同，相同则不记录
  3. 释放循环队列中最旧的历史命令内存
  4. 分配新内存并复制当前命令
  5. 更新历史命令索引和最大命令长度
  6. 在`inner_shell_deal_parse_phase()`中调用，当用户按下回车键时

#### `inner_shell_get_history_cmd(VOID)`
- **作用**：从历史命令中获取当前光标指向的命令，复制到缓冲区中。
- **限制**：
  - 需要确保`history_cursor`指向有效的历史命令
  - 不检查缓冲区大小是否足够
- **使用流程**：
  1. 清空当前缓冲区
  2. 从`history_cmds[history_cursor]`复制命令到缓冲区
  3. 更新缓冲区光标位置和大小
  4. 在上下箭头键处理函数中调用

#### `inner_shell_check_equal_in_last_two_char(VOID)`
- **作用**：检查最近输入的两个字符是否相同。用于历史命令导航的边界判断。
- **限制**：
  - 仅检查最近两个字符，不检查更早的历史
- **使用流程**：
  1. 比较`shell_cur_char`和`shell_pre_input_char`
  2. 返回`TRUE`表示两个字符相同，`FALSE`表示不同
  3. 在上下箭头键处理函数中调用，用于判断是否到达历史命令边界

### 特殊键处理函数

#### `inner_shell_uarrow_key_do()`
- **作用**：处理上箭头键（↑）按下事件。浏览上一条历史命令。
- **限制**：
  - 不支持循环浏览（到达最早命令后停止）
  - 需要历史命令存在才能工作
- **使用流程**：
  1. 检查是否有历史命令，没有则直接返回
  2. 更新历史命令光标索引（向前移动）
  3. 检查是否到达边界，到达则重置缓冲区
  4. 调用`inner_shell_get_history_cmd()`获取历史命令
  5. 重置命令行并显示获取的命令

#### `inner_shell_darrow_key_do()`
- **作用**：处理下箭头键（↓）按下事件。浏览下一条历史命令。
- **限制**：
  - 不支持循环浏览（到达最新命令后停止）
  - 需要历史命令存在才能工作
- **使用流程**：
  1. 检查是否有历史命令，没有则直接返回
  2. 更新历史命令光标索引（向后移动）
  3. 检查是否到达边界，到达则重置缓冲区
  4. 调用`inner_shell_get_history_cmd()`获取历史命令
  5. 重置命令行并显示获取的命令

#### `inner_shell_larrow_key_do()`
- **作用**：处理左箭头键（←）按下事件。将光标向左移动一个字符。
- **限制**：
  - 光标不能移动到缓冲区开始位置之前
  - 在缓冲区开始位置有特殊处理
- **使用流程**：
  1. 检查光标是否在缓冲区开始位置
  2. 如果不在开始位置，光标左移一位
  3. 如果在开始位置，显示特殊提示（空格或第一个字符）
  4. 更新光标位置

#### `inner_shell_rarrow_key_do()`
- **作用**：处理右箭头键（→）按下事件。将光标向右移动一个字符。
- **限制**：
  - 光标不能移动到缓冲区末尾位置之后
  - 在缓冲区末尾位置有特殊处理
- **使用流程**：
  1. 检查光标是否在缓冲区末尾位置
  2. 如果不在末尾位置，光标右移一位
  3. 如果在末尾位置，执行退格操作（特殊处理）
  4. 更新光标位置

#### `inner_shell_del_key_do(VOID)`
- **作用**：处理删除键（DEL）按下事件。删除光标前的一个字符。
- **限制**：
  - 缓冲区为空时无操作
  - 光标在开始位置时有特殊处理
- **使用流程**：
  1. 重置命令行显示
  2. 检查缓冲区是否为空，为空则返回
  3. 检查光标位置，在开始位置则特殊处理
  4. 创建临时缓冲区保存删除点后的内容
  5. 重新组织缓冲区内容（删除字符）
  6. 更新缓冲区大小和光标位置
  7. 重新显示缓冲区内容

#### `inner_shell_tab_key_do(VOID)`
- **作用**：处理Tab键按下事件。实现命令补全功能。
- **限制**：
  - 仅支持命令名补全，不支持参数补全
  - 多个匹配命令时显示列表但不自动补全
- **使用流程**：
  1. 获取匹配当前输入的前缀的命令数量
  2. 分配内存存储匹配的命令名指针
  3. 遍历命令链表，收集匹配的命令
  4. 如果只有一个匹配命令，自动补全
  5. 如果有多个匹配命令，显示命令列表
  6. 释放临时内存
  7. 在`inner_shell_deal_switch_phase()`中调用

#### `inner_shell_reset_line(VOID)`
- **作用**：重置命令行显示。清除当前行并重新显示Shell提示符。
- **限制**：
  - 使用ANSI转义序列清屏，依赖终端支持
- **使用流程**：
  1. 使用`SHELL_CLEAN_LINE`（"\033[2K\r"）清除当前行
  2. 使用`SHELL_NAME`（"OSZ$ "）显示Shell提示符
  3. 在多种场景中调用：历史命令导航、命令执行后、错误处理等

#### `inner_shell_get_cmd_key_count_by_tab()`
- **作用**：获取通过Tab键匹配的命令数量。统计命令链表中命令的总数。
- **限制**：
  - 仅统计总数，不进行前缀匹配
- **使用流程**：
  1. 遍历命令链表
  2. 统计节点数量
  3. 返回命令总数
  4. 在`inner_shell_tab_key_do()`中调用，用于分配内存

#### `inner_shell_get_cmd_key_by_tab(UINT32 *keys, CHAR *input)`
- **作用**：获取通过Tab键匹配的命令名指针。根据输入前缀过滤命令。
- **限制**：
  - 需要预先分配足够的内存空间
  - 仅返回命令名指针，不复制字符串
- **使用流程**：
  1. 遍历命令链表
  2. 使用`strncmp()`比较命令名前缀
  3. 将匹配的命令名指针存储到`keys`数组中
  4. 返回匹配的命令数量
  5. 在`inner_shell_tab_key_do()`中调用

### 状态机处理函数

#### `inner_shell_deal_get_phase()`
- **作用**：处理GET状态阶段的输入。从FIFO读取字符，区分普通字符和特殊字符，更新缓冲区。
- **限制**：
  - 依赖FIFO队列正常工作
  - 缓冲区满时无法处理新字符
- **使用流程**：
  1. 检查缓冲区是否已满，满则设置错误状态
  2. 保存前一个字符，从FIFO读取当前字符
  3. 检查FIFO读取是否成功，失败则设置错误状态
  4. 判断字符是否为特殊字符，是则切换到SWITCH状态
  5. 处理普通字符：插入缓冲区，更新光标位置
  6. 如果光标已偏移，重新打印缓冲区内容
  7. 输出字符到终端

#### `inner_shell_deal_switch_phase()`
- **作用**：处理SWITCH状态阶段的特殊字符。识别并处理各种特殊键（删除、Tab、回车、方向键等）。
- **限制**：
  - 需要正确解析ESC序列（ESC+[+A/B/C/D）
  - 依赖前一个状态正确设置
- **使用流程**：
  1. 根据当前字符识别特殊键类型
  2. 删除键：调用`inner_shell_del_key_do()`
  3. Tab键：调用`inner_shell_tab_key_do()`
  4. 回车键：切换到PARSE状态
  5. ESC键：继续读取下一个字符（ESC序列开始）
  6. 左方括号键：继续读取下一个字符（ESC序列第二部分）
  7. 方向键（A/B/C/D）：调用相应的方向键处理函数
  8. 其他字符：保持SWITCH状态继续处理

#### `inner_shell_deal_parse_phase()`
- **作用**：处理PARSE状态阶段的命令解析。解析命令名和参数，匹配注册的命令。
- **限制**：
  - 命令名长度受`SHELL_CMD_KEY_LEN_MAX`限制
  - 参数数量受命令注册时指定的`max_argc`限制
- **使用流程**：
  1. 记录当前命令到历史命令中
  2. 将缓冲区中的空格替换为`\0`，分割参数
  3. 检查命令名长度是否超限，超限则设置错误状态
  4. 提取命令名
  5. 遍历命令链表，查找匹配的命令
  6. 如果找到匹配命令，解析参数并分配参数数组
  7. 设置当前命令指针，切换到EXC状态
  8. 如果未找到命令，设置当前命令为NULL，切换到EXC状态

#### `inner_shell_deal_exc_phase()`
- **作用**：处理EXC状态阶段的命令执行。调用匹配命令的回调函数执行命令逻辑。
- **限制**：
  - 依赖命令回调函数正确实现
  - 需要正确处理参数内存释放
- **使用流程**：
  1. 重置Shell状态为NONE
  2. 获取当前命令指针
  3. 如果命令存在，调用命令回调函数执行命令
  4. 如果命令不存在，显示"未找到命令"错误信息
  5. 清空缓冲区，重置光标位置
  6. 释放参数数组内存（如果存在）
  7. 重置历史命令光标为无效状态
  8. 输出换行符并重置命令行显示

#### `inner_shell_deal_err_phase()`
- **作用**：处理ERR状态阶段的错误恢复。清理错误状态，重置缓冲区，报告错误码。
- **限制**：
  - 仅处理Shell模块内部错误，不处理命令执行错误
- **使用流程**：
  1. 清空缓冲区内容
  2. 重置缓冲区大小和光标位置
  3. 清除错误代码
  4. 重置Shell状态为NONE
  5. 显示错误码（十六进制格式）
  6. 输出换行符并重置命令行显示

### 辅助函数

#### `inner_shell_check_params(CMD_PARAMS *params)`
- **作用**：检查命令参数的有效性。验证命令名和回调函数是否有效。
- **限制**：
  - 仅进行基本验证，不验证命令名是否重复
- **使用流程**：
  1. 检查命令名是否为空字符串
  2. 检查回调函数指针是否为NULL
  3. 返回`OS_OK`表示参数有效，返回错误码表示无效
  4. 在`shell_register_cmd()`中调用，确保注册的命令参数有效

#### `shell_loop(VOID)`
- **作用**：Shell主循环函数。实现状态机的主循环逻辑，处理各种状态转换。
- **限制**：
  - 作为独立任务运行，需要任务调度支持
  - 依赖全局状态变量`g_shell_cb.shell_state`
- **使用流程**：
  1. 重置命令行显示
  2. 进入无限循环：
     - NONE状态：检查FIFO队列，非空则切换到GET状态，否则睡眠20ms
     - GET状态：调用`inner_shell_deal_get_phase()`处理输入
     - SWITCH状态：调用`inner_shell_deal_switch_phase()`处理特殊字符
     - PARSE状态：调用`inner_shell_deal_parse_phase()`解析命令
     - EXC状态：调用`inner_shell_deal_exc_phase()`执行命令
     - ERR状态：调用`inner_shell_deal_err_phase()`处理错误
  3. 根据状态执行相应操作，实现完整的状态机循环

### 公共接口（非STATIC但属于模块核心）

#### `shell_register_cmd(CMD_PARAMS *params)`
- **作用**：注册动态命令。将命令参数添加到命令链表中，支持运行时命令注册。
- **限制**：
  - 命令名不能为空，回调函数不能为NULL
  - 命令名长度受`SHELL_CMD_KEY_LEN_MAX`限制
- **使用流程**：
  1. 使用`ASSERT()`检查参数指针有效性
  2. 调用`inner_shell_check_params()`验证参数
  3. 分配`CMD_NODE`结构体内存
  4. 复制命令参数到节点中
  5. 将节点插入命令链表尾部
  6. 在系统初始化或模块加载时调用

#### `shell_write_fifo(CHAR c)`
- **作用**：向Shell的FIFO队列写入字符。通常由UART中断服务程序调用，实现异步输入。
- **限制**：
  - FIFO队列满时会丢弃字符
  - 需要确保FIFO队列已正确初始化
- **使用流程**：
  1. 获取Shell控制块中的FIFO指针
  2. 调用`fifo_write()`将字符写入FIFO
  3. 使用`FIFO_WRITE_STOP`模式，队列满时停止写入
  4. 在UART中断处理函数中调用

#### `shell_read_fifo(VOID)`
- **作用**：从Shell的FIFO队列读取字符。在GET状态阶段调用，获取用户输入。
- **限制**：
  - FIFO队列为空时返回0
  - 需要确保FIFO队列已正确初始化
- **使用流程**：
  1. 获取Shell控制块中的FIFO指针
  2. 调用`fifo_read()`读取一个字符
  3. 将读取的字符存储到`g_shell_cb.shell_cur_char`
  4. 返回读取的字符数量（1表示成功，0表示失败）
  5. 在`inner_shell_deal_get_phase()`中调用

#### `shell_get_state(VOID)`
- **作用**：获取Shell当前状态。用于外部模块查询Shell运行状态。
- **限制**：
  - 仅返回状态值，不提供状态语义解释
- **使用流程**：
  1. 返回`g_shell_cb.shell_state`的当前值
  2. 在需要监控Shell状态的外部模块中调用

#### `shell_set_state(SHELL_STATE state)`
- **作用**：设置Shell状态。用于外部模块控制Shell状态转换。
- **限制**：
  - 需要确保设置的状态值有效
  - 不推荐外部模块随意修改Shell状态
- **使用流程**：
  1. 将`state`参数赋值给`g_shell_cb.shell_state`
  2. 在需要控制Shell状态的外部模块中谨慎调用
