1.3 设计目标与非目标

目标
  • 释放时自动与物理相邻的空闲块合并（前、后、双向）。
  • 分配策略名实相符：满足请求的最小空闲块（best-fit）。
  • 不改变对外 API 签名与调用方语义。
  • 消除失败路径上的空指针解引用。
  • 用户指针 16 字节对齐，满足 RISC-V psABI 的栈对齐要求。
  • 可在宿主机上离线验证（不启动 QEMU）。
非目标（本次不做）
  • 不引入 MMU / 分页 / 虚拟内存。
  • 不做多桶（segregated bins）或位图分配器，保持单链表。
  • 不做内存越界检测、堆栈水位、泄漏追踪（另立需求）。
  • 不追求 O(1) 分配；块数量级为 10¹～10²，O(n) 扫描足够。
  • 不改链接脚本堆区间与 DTCM 布局。

2.2 现有分配语义

os_mem_get_next_bestfit_free() 的真实行为是“先找尺寸完全相等的块；否则取遍历到的最后一个空闲块切分”，并非最小满足块：

// bestfit.c:32-39 —— 只有尺寸完全相等才返回 TRUE
STATIC BOOL os_is_bestfit_free(MEM_NODE_INFO *free_node, UINT32 size)
{
    UINT32 expect_size = ALIGN_UP(size, 0x10);
    if (MEM_NODE_GET_SIZE(free_node) == expect_size) return TRUE;
    return FALSE;
}
情形实际结果后果
链表中存在尺寸恰好相等的空闲块直接返回该块内部碎片最少，但概率低
无精确匹配对遍历“最后”一个空闲块切分切掉的是大块尾巴，留下小碎片，与请求大小无关
最后一个空闲块也不够大os_mem_split_node 返回 NULL → 上层返回 NULLosz_malloc 立刻对 NULL 解引用

2.3 现有释放语义

释放路径只有三步：指针减 16 得到块头 → 清 used 位 → 结束。没有邻块探测，没有链表重排，也没有临界区：

03方案选型与总体设计

3.1 合并的实现路径对比

方案邻块定位方式单次 free 时间块头开销改动规模结论
A. 按地址链表 + 全表扫描找邻遍历空闲链表，比对 addr+sizeO(n²) 最坏0小不可取：块多时抖动明显
B. 只维护后继块 used 位（无 prev_size）后继可算，前驱不可得O(1) 仅后向0小只能单向合并，碎片仍残留
C. 边界标记（size + prev_size）前后邻均 O(1) 地址计算O(1) 探测 + O(n) 入链0（复用保留字）中选用，工业界通用做法
D. 分离空闲链表 / 位图同 C接近 O(1)额外桶数组大当前规模不需要，列为演进方向

3.2 总体设计要点

  1. 块头固定 16 B：8 B 链表指针 + 4 B size/used + 4 B prev_size。复用原 rsv_for_free/magic_num 占位，不增加单块开销。
  2. 独立空闲链表哨兵：MEM_HEAD_INFO.free_list 作为头，终止节点 end_node 专职物理链终点，不再兼任哨兵。
  3. 物理链与空闲链分离：物理链通过地址算术遍历；空闲链只挂空闲块，按尺寸升序。
  4. 分配 = best-fit + 低端切分 + rem 归并：升序链中第一个满足请求的块就是最小满足块；从低地址切出请求量，剩余块在高地址；切分后若 rem 与后邻空闲，立即出链合并，避免产生“相邻两块同时空闲”的中间态。
  5. 释放 = 置空闲 + 后向合并 + 前向合并 + 入链，合并后维护后继块的 prev_size。
  6. 最小切分阈值：剩余不足 0x20（块头 16 + 最小数据 16）时不切分，整块交付，从根上消除 0 尺寸块。
  7. 临界区：malloc/free 全程 ARCH_INT_LOCK/UNLOCK，与任务模块保持同一把“中断锁”。
  8. 调试自检：仅由功能宏 MEM_FEATURE_DEBUG 控制；打开只追加 magic、边界一致性、链表有序性等自检，基础校验与功能路径两种配置完全一致。

4.2 类型定义

/* bestfit.h —— 改造后 */
/* rv32 口径：三份描述符均 16 B，first_node = pool + 32，用户指针恒 16 B 对齐。
   宿主单测（64 位指针）分支按 sizeof 取值，算法/不变量不变。 */
#if __SIZEOF_POINTER__ == 4
#define MEM_NODE_INFO_SIZE      (16U)
#define MEM_POOL_INFO_SIZE      (16U)   /* 原 12 → 补到 16，保证 head 16 对齐 */
#define MEM_HEAD_INFO_SIZE      (16U)
#define MEM_ALIGN               (16U)   /* psABI 对齐粒度，同时是块粒度 */
#else
#define MEM_NODE_INFO_SIZE      ((UINT32)sizeof(MEM_NODE_INFO))   /* 宿主：24 */
#define MEM_POOL_INFO_SIZE      ((UINT32)sizeof(MEM_POOL_INFO))
#define MEM_HEAD_INFO_SIZE      ((UINT32)sizeof(MEM_HEAD_INFO))
#define MEM_ALIGN               (8U)    /* 宿主 64 位指针 */
#endif
#define MEM_MIN_SPLIT           (0x20U) /* 剩余数据区不足此值则整块交付；同时是最小分配块 */

#define MEM_SIZE_MASK           (0x7FFFFFFFU)
#define MEM_USED_MASK           (0x80000000U)
#define MEM_NODE_GET_SIZE(n)    ((n)->size_and_used & MEM_SIZE_MASK)
#define MEM_NODE_SET_SIZE(n,s)  ((n)->size_and_used = (MEM_NODE_GET_USED(n) | ((s) & MEM_SIZE_MASK)))
#define MEM_NODE_GET_USED(n)    ((n)->size_and_used & MEM_USED_MASK)
#define MEM_NODE_SET_USED(n)    ((n)->size_and_used |= MEM_USED_MASK)
#define MEM_NODE_CLR_USED(n)    ((n)->size_and_used &= (~MEM_USED_MASK))
#define MEM_PREV_MAGIC_MASK     (0xC0000000U)
#define MEM_PREV_MAGIC          (0x80000000U)
#define MEM_PREV_SIZE_MASK      (0x3FFFFFFFU)
#define MEM_NODE_GET_PREV(n)    ((n)->prev_size & MEM_PREV_SIZE_MASK)
#define MEM_NODE_SET_PREV(n,s)  ((n)->prev_size = (MEM_PREV_MAGIC | ((s) & MEM_PREV_SIZE_MASK)))
#define MEM_NODE_GET_DATA(n)    ((UINTPTR)((UINT8 *)(n) + MEM_NODE_INFO_SIZE))
#define MEM_NODE_NEXT(n)        ((MEM_NODE_INFO *)((UINT8 *)(n) + MEM_NODE_INFO_SIZE + MEM_NODE_GET_SIZE(n)))
#define MEM_NODE_PREV(n)        ((MEM_NODE_INFO *)((UINT8 *)(n) - MEM_NODE_INFO_SIZE - MEM_NODE_GET_PREV(n)))

typedef struct {
    DLINK_NODE node_list;      /* 8 B：空闲链表挂钩，占用块内容无效 */
    UINT32     size_and_used;  /* 4 B：size[30:0] | used[31] */
    UINT32     prev_size;      /* 4 B：前邻数据区大小，0 = 无前邻 */
} MEM_NODE_INFO;               /* sizeof == 16 on rv32 */

typedef struct {
    DLINK_NODE     free_list;  /* 独立哨兵：只挂空闲块，size 升序 */
    MEM_NODE_INFO *first_node;
} MEM_HEAD_INFO;               /* sizeof == 12 ≤ MEM_HEAD_INFO_SIZE(16)，补齐到 16 对齐 */

/* 终止节点不入结构体，由堆尾地址推算，避免描述符超长 */
#define MEM_END_NODE(pool_end)  ((MEM_NODE_INFO *)((UINT8 *)(pool_end) - MEM_NODE_INFO_SIZE))
#define MEM_MAX_ALLOC          ((UINT32)DEFAULT_HEAP_SIZE - MEM_POOL_INFO_SIZE - MEM_HEAD_INFO_SIZE)
对齐处理（已定）：采用方案①——MEM_HEAD_INFO 不再保存 end_node 指针，终止节点由 g_heap_end − 16 计算；MEM_POOL_INFO 与 MEM_HEAD_INFO 的分配尺寸常量均取 16，使 first_node 落在 pool + 32，恒 16 B 对齐。该取舍将在评审中确认，若不接受则退化为“常量 32 + 补齐”。

05算法设计

5.1 初始化

VOID inner_mem_init(VOID *pool, UINT32 pool_size)
{
    g_mempool = (MEM_POOL_INFO *)pool;                    /* pool 16 对齐 */
    MEM_HEAD_INFO *head = (MEM_HEAD_INFO *)((UINT8 *)pool + MEM_POOL_INFO_SIZE);
    dlink_init(&head->free_list);
    head->first_node = (MEM_NODE_INFO *)((UINT8 *)head + MEM_HEAD_INFO_SIZE);

    UINT32 data_size = pool_size - MEM_POOL_INFO_SIZE - MEM_HEAD_INFO_SIZE - 2 * MEM_NODE_INFO_SIZE;
    data_size = ALIGN_DOWN(data_size, MEM_ALIGN);         /* 数据区必须 16 的倍数 */

    head->first_node->size_and_used = data_size;          /* used=0 */
    head->first_node->prev_size    = 0;
    inner_free_list_insert(head->first_node);

    MEM_NODE_INFO *end = (MEM_NODE_INFO *)((UINT8 *)head->first_node + MEM_NODE_INFO_SIZE + data_size);
    end->size_and_used = MEM_USED_MASK;                   /* size=0, used=1 */
    end->prev_size = data_size;
}

对外入口保持 osz_memory_init()，内部转调 inner_mem_init(DEFAULT_HEAP_START, (UINT32)DEFAULT_HEAP_SIZE)。inner_mem_init 带显式尺寸，是宿主单测可注入“假堆”的关键。

5.2 分配算法

伪代码

UINT32 inner_mem_alloc(UINT32 size, VOID **out)
{
    if (out == NULL)                       return MEM_IS_NULL_ERR;
    *out = NULL;
    if (size == 0 || size > MEM_MAX_ALLOC)  return MEM_SIZE_INVALID_ERR;
    if (g_mempool == NULL)                  return MEM_POOL_NOT_INIT_ERR;

    UINT32 need = ALIGN_UP(size, MEM_ALIGN);
    if (need < MEM_MIN_SPLIT)   need = MEM_MIN_SPLIT;   /* 最小分配块 32 B */
    UINT32 int_save;
    ARCH_INT_LOCK(int_save);                /* 临界区开始 */

    MEM_NODE_INFO *blk = inner_best_fit(need);          /* 升序链首个 size≥need */
    if (blk == NULL) {
        ARCH_INT_UNLOCK(int_save);
        return MEM_NO_FREE_BLK_ERR;
    }

    /* size - need 里还含 rem 的 16 B 块头，阈值要比 MIN_SPLIT 多一个块头 */
    if ((MEM_NODE_GET_SIZE(blk) - need) < (MEM_MIN_SPLIT + MEM_NODE_INFO_SIZE)) {
        inner_free_list_remove(blk);                    /* 整块交付 */
        MEM_NODE_SET_USED(blk);
    else {
        MEM_NODE_INFO *rem = (MEM_NODE_INFO *)((UINT8 *)blk + MEM_NODE_INFO_SIZE + need);
        MEM_NODE_SET_SIZE(rem, MEM_NODE_GET_SIZE(blk) - MEM_NODE_INFO_SIZE - need);
        rem->prev_size = need;
        MEM_NODE_CLR_USED(rem);

        inner_free_list_remove(blk);
        MEM_NODE_SET_SIZE(blk, need);
        MEM_NODE_SET_USED(blk);

        /* 防御性合并：rem 的后邻若空闲，必须先归一再入链，
           否则会留下“相邻两块同时空闲”的中间态，破坏 I7。 */
        MEM_NODE_INFO *next = MEM_NODE_NEXT(rem);
        if (next != inner_end_node() && MEM_NODE_GET_USED(next) == 0) {
            inner_free_list_remove(next);
            MEM_NODE_SET_SIZE(rem, MEM_NODE_GET_SIZE(rem) + MEM_NODE_INFO_SIZE + MEM_NODE_GET_SIZE(next));
        }
        MEM_NODE_NEXT(rem)->prev_size = MEM_NODE_GET_SIZE(rem);   /* I4 */
        inner_free_list_insert(rem);                              /* size 升序入链 */
    }

    *out = (VOID *)MEM_NODE_GET_DATA(blk);
    ARCH_INT_UNLOCK(int_save);              /* 临界区结束 */
    return OS_OK;
}
为什么切分后还要再看一次后邻：正常不变量（I7）下，被切分的空闲块其物理后继必然已占用或为 end_node，因为 free 已把相邻空闲块合并干净，所以该分支理论上不可达。但它是防御性必需：一旦后续加入“批量释放 / 延迟合并 / 中断安全池”等路径，或 free 的合并被裁剪，这个分支就是唯一能阻止“相邻空闲块并存”的兜底；代价仅一次 O(1) 地址计算与一次条件判断。
为什么必须低端切分：高地址剩余块的首地址由 need 精确算出，且剩余块只需维护一个 prev_size；若像现状那样从高端切，切出来的块 prev_size 要回填、原块的 next 关系也要改，两次写放大。低端切分还顺带让“分配后地址单调增长”更符合调试预期。

5.3 释放与合并

释放分三步：置空闲 → 与后邻合并 → 与前邻合并，最后统一入链。四种组合如图：

与 split 侧的 rem 归并一起，这两条路径共同维持不变量 I7：堆中不存在“物理相邻的两块同时空闲”。MEM_FEATURE_DEBUG 打开时，每次操作后可全遍历物理链做一次 I7 自检；该宏只加自检，不改变合并路径。

释放不做清零：free 只更新块头（used 位、合并后的 size、后继 prev_size），不写用户数据区。这是已确认的性能取舍；若后续有安全擦除需求，另加显式接口，不挂配置开关。

伪代码

UINT32 inner_mem_free(VOID *ptr)
{
    if (ptr == NULL)              return MEM_IS_NULL_ERR;
    MEM_NODE_INFO *node = (MEM_NODE_INFO *)((UINT8 *)ptr - MEM_NODE_INFO_SIZE);

    UINT32 int_save;
    ARCH_INT_LOCK(int_save);
    if (inner_check_node(node) != OS_OK) {          /* Debug 配置生效 */
        ARCH_INT_UNLOCK(int_save);
        return MEM_NODE_CORRUPTED_ERR;
    }
    if (MEM_NODE_GET_USED(node) == 0) {            /* 重复释放 */
        ARCH_INT_UNLOCK(int_save);
        return MEM_DOUBLE_FREE_ERR;
    }
    MEM_NODE_CLR_USED(node);

    /* ① 后向合并 */
    MEM_NODE_INFO *next = MEM_NODE_NEXT(node);
    if (next != inner_end_node() && MEM_NODE_GET_USED(next) == 0) {
        inner_free_list_remove(next);
        MEM_NODE_SET_SIZE(node, MEM_NODE_GET_SIZE(node) + MEM_NODE_INFO_SIZE + MEM_NODE_GET_SIZE(next));
    }

    /* ② 前向合并 */
    if (node->prev_size != 0) {
        MEM_NODE_INFO *prev = MEM_NODE_PREV(node);
        if (MEM_NODE_GET_USED(prev) == 0) {
            inner_free_list_remove(prev);
            MEM_NODE_SET_SIZE(prev, MEM_NODE_GET_SIZE(prev) + MEM_NODE_INFO_SIZE + MEM_NODE_GET_SIZE(node));
            node = prev;                            /* 合并块以 prev 为首 */
        }
    }

    /* ③ 维护后继边界并统一入链 */
    MEM_NODE_NEXT(node)->prev_size = MEM_NODE_GET_SIZE(node);
    inner_free_list_insert(node);                  /* size 升序 */

    ARCH_INT_UNLOCK(int_save);
    return OS_OK;
}

5.4 空闲链表维护

链表以 head->free_list 为哨兵，按 size 严格升序。插入与删除都是 O(n)/O(1)：

STATIC VOID inner_free_list_insert(MEM_NODE_INFO *node)
{
    DLINK_NODE *pos = g_mempool->head->free_list.next;
    while (pos != &g_mempool->head->free_list) {
        MEM_NODE_INFO *cur = STRUCT_ENTRY(MEM_NODE_INFO, node_list, pos);
        if (MEM_NODE_GET_SIZE(cur) > MEM_NODE_GET_SIZE(node)) break;
        pos = pos->next;
    }
    dlink_insert_head(pos, &node->node_list);      /* 插到首个更大块之前 */
}

STATIC MEM_NODE_INFO *inner_best_fit(UINT32 need)
{
    DLINK_NODE *pos;
    DLINK_FOREACH(pos, &g_mempool->head->free_list) {
        MEM_NODE_INFO *cur = STRUCT_ENTRY(MEM_NODE_INFO, node_list, pos);
        if (MEM_NODE_GET_SIZE(cur) >= need) return cur;   /* 升序 ⇒ 首个即最优 */
    }
    return NULL;
}
与现状的关键差异：不再把“占用块”留在空闲链表里过滤，也不再以 end_node 兼作哨兵。这样每次操作只剩“真正的空闲块”需要维护，链表长度等于碎片数，best-fit 扫描成本随碎片数而不是总块数增长。

6.4 宏分层：配置宏与功能宏

原则：配置宏只在派生头出现一次，业务代码只认功能宏。配置宏来自 Kconfig 生成，开时为 1、关时不定义（kconfiglib 行为）；功能宏由模块派生且恒有定义、恒为 0/1，从根本上消除 #ifdef 在“值为 0 仍成立”时的不一致。

6.7 分层依据与参照实现

6.4–6.6 的规则不是为了多一层间接，而是本项目三个具体约束推出来的结果；机制形态参照了成熟内核，但使用面比它们更窄。

依据一：单一来源。本项目配置实际存在四处可能取值的地方——kernel/Kconfig、生成的 targets/platform/include/menuconfig.h、construct/cmake/cfg.cmake 里另抄的一份默认值、以及宿主侧 test/include/menuconfig.h（空桩）。引用面越宽，漂移点越多；收敛到 mem_feature.h 一处后，越界引用只要一次 grep OSZ_CFG_ 就能查干净（对应 11 章 R-08、A1）。

依据二：取值封闭。Kconfig 生成的语义是“开 = #define X 1，关 = 不定义”。于是 #if OSZ_CFG_MEM_DEBUG 在关闭时会因宏不存在而直接编译失败，#ifdef 又区分不了“没定义”和“定义成 0”，两种写法都无法覆盖三态。唯一稳妥的做法是先收敛成恒 0/1 的功能宏，再对越界取值 #error（A2、T-24）。

依据三：接口与 ABI 不随配置变化。本项目没有模块机制，宿主测试与目标机是两套独立产物，配置一旦影响结构体布局或函数签名，没有任何机制能发现两边不一致。Linux 敢让 CONFIG_* 影响结构体字段，靠的是“全量重编 + 模块 vermagic 校验”这条兜底链；我们没有这条链，所以把影响面直接切掉。

参照配置来源与生成头代码消费方式ABI 影响与一致性兜底
LinuxKconfig → include/generated/autoconf.h；开为 #define CONFIG_X 1，关为不定义include/linux/kconfig.h 的 IS_ENABLED() 把“定义与否”转成 0/1 常量表达式，可放进 if()，编译器因此对两个分支都做类型检查并折叠死代码；但内核并不禁止 #ifdef CONFIG_*，头文件里按配置裁剪字段是常态允许改变结构体（bool/tristate、页大小、SMP 都会改布局）；兜底靠全量重编 + 模块 vermagic 与 BUILD_BUG_ON
Zephyr同源 Kconfig，生成 include/zephyr/autoconf.h，前缀 CONFIG_业务代码直接引用 CONFIG_*，组件存在性也由配置决定允许改变布局（设备树与驱动裁剪）；兜底靠每次构建全量生成头文件
FreeRTOS无 Kconfig，单个手写 FreeRTOSConfig.h 是唯一配置来源业务代码直接消费 configXXX 常量不鼓励改变布局，靠人工纪律；单头即单一来源，天然不漂移
本设计Kconfig（仅 OSZ_CFG_MEM_DEBUG 一项）→ menuconfig.h → mem_feature.h 收敛为 MEM_FEATURE_DEBUG 恒 0/1 + 结构常量业务代码只见功能宏；禁止 #ifdef、禁止直接引用 OSZ_CFG_*不允许：块头 16 B、API 签名两配置一致；兜底靠单一派生口 + #error + 双配置回归（A6）

取舍说明：抄的是 Linux 的机制骨架——生成头、“不定义即关闭”、用 0/1 常量做编译期折叠而不是 #ifdef 分支（这样关闭时另一分支仍参与编译，不至于腐烂）。不抄的是它的使用面：Linux 允许 CONFIG_* 散落在任意文件、允许改变结构体布局，因为它有 vermagic 这类兜底；我们的宿主空桩会让同一份源码在两套环境取到不同值，只能靠“唯一派生头 + 常量”来保证一致。FreeRTOS 的 FreeRTOSConfig.h 提供了“单头即单一来源”的思路，但它把配置项也放在手写头里；我们仍走 Kconfig，避免多一份手写副本。

边界：这套做法是“Linux 机制 + 更窄使用面”的裁剪版，不是照搬。若后续要把同一风格推广到 task、ipc 等模块，可以各自建立 *_feature.h，但那属于平台层统一议题，不在本文范围。

8.2 兼容性结论

  • API 零变更：三个对外函数签名、返回值语义不变；NULL 仍是唯一失败信号。
  • ABI 变更：堆内块地址序列改变（低端切分），但没有任何调用点依赖块地址顺序或相邻关系。
  • 对齐增强：用户指针由 8 B 对齐提升到 16 B 对齐，属于修正而非破坏；唯一风险是若有代码用“块地址 − 16”反推块头，仍成立。
  • 内存开销：块头仍 16 B；池/头描述符由 12+12 补到 16+16，净增 8 B，全堆一次。
  • 配置与功能宏：OSZ_CFG_MEM_DEBUG 默认关闭，经 mem_feature.h 派生为恒为 0/1 的 MEM_FEATURE_DEBUG；打开只增加自检开销，不改变 API 与行为。
需要同步更新的文档：doc/kernel_doc/shell/4-Shell内存分配设计.md 目前只描述“按需分配 + 及时释放”，未涉及底层碎片行为；本次实施后需补一句“分配器已支持相邻空闲块合并”，避免文档与实现脱节。

09可测试性设计

9.1 宿主测试方案

test/ 是独立 CMake 工程，用宿主 gtest 编译与架构无关的纯 C 模块。内存模块需解决两个依赖：

T-08仅后邻合并A占 / B / C空 释放 BB+C 合并；free_list 数量 −1；后继 prev_size 更新
T-09仅前邻合并A空 / B / C占 释放 BA+B 合并，块首为 A；地址区间正确
T-10前后都合并A空 / B / C空 释放 BA+B+C 归一；出链 2 次；链表仍升序
T-11无邻可并A占 / B / C占 释放 BB 独立入链，位置符合升序
T-12首块边界释放 first_node 位置上的块prev_size=0 不探测前驱，不越界
T-13尾块边界释放最后一个块后继为 end_node，不合并；end 仍 USED
T-14重复释放同一指针 free 两次两种配置均返回 MEM_DOUBLE_FREE_ERR，堆不被二次入链
T-15非法指针free 栈地址 / 未对齐指针Debug 下返回 MEM_NODE_CORRUPTED_ERR
T-16free(NULL)osz_free(NULL)无操作，不崩溃
T-17碎片回归交替申请 1/2/3/4 块并全部释放堆恢复为单个空闲块，size 等于初始值
T-18链表有序性随机 100 次分配/释放后遍历size 严格升序、无重复节点、全部 used==0
T-19物理链完整性任意操作序列后遍历从 first_node 走到 end_node 恰好覆盖数据区，无重叠
T-20影子模型随机压力1000 次随机 malloc/free（带 4 KB 独立位图）每次分配区间不与已用区间重叠；释放后位图同步；不崩溃
T-21切分后的 rem 归并白盒构造：被切分块的后继也是空闲块（直接篡改块头模拟非法中间态）malloc 切分后 rem 与后邻归一；后邻已出链；rem.size = 原剩余 + 16 + 后邻 size；新后继 prev_size 正确
T-22无相邻空闲块（I7）1000 次随机 malloc/free 后遍历物理链任意相邻两块不同时 used==0；end_node 仍 USED
T-23双配置行为一致同一用例集分别以 OSZ_CFG_MEM_DEBUG=0 与 =1 编译运行外部返回结果完全一致；仅 Debug 多出自检失败路径；两种配置都无崩溃
T-24功能宏取值封闭故意以 OSZ_CFG_MEM_DEBUG=2 构建编译阶段触发 #error，不产生产物
T-25释放不清零写入特征值 → free → 再 malloc 同尺寸并读原位置未发生覆写前内容保持特征值（仅验证不 memset）

9.3 影子模型

为避免“自己验证自己”，T-20 用一维 bool bitmap[heap_size/16] 独立记录每个 16 B 单元是否被用户占用：分配时把返回区间逐格置位并检查原值为假；释放时清零。该模型不读取任何块头信息，能独立发现重叠、越界和漏合并导致的“假空闲”。

10性能与资源

10.1 复杂度

操作现状设计后说明
mallocO(N)，N = 全部块（含占用）O(F)，F = 空闲块只遍历空闲链；另有 1 次 O(1) 后邻探测
freeO(1)O(1) 探测 + O(F) 入链合并本身常数
单块空间开销16 B16 B无变化
堆固定开销24 B（池+头）32 B+8 B，仅一次
最小可分配块16 B（可产生 0 尺寸块）32 B（16 头 + 16 数据）消除退化块

10.2 实测口径

  • 以 rdcycle 计数：在 DTCM 堆上执行 1000 次 0x40 字节申请+释放，记录 malloc/free 的 cycle 上界。
  • 碎片率：连续执行 Shell 历史命令模拟（长度 8/16/32/64 循环，容量 16 条），统计“申请失败次数”与“最大可分配块”。
  • 基线对比：同一脚本在 main（无合并）与 feature 分支各跑一次，作为交付证据附在 MR 描述中。

10.3 预期收益

典型收益：Shell 环形历史（16 条）持续输入不同长度命令时，无合并版本会留下大量 16～80 B 的不可复用碎片；合并版本在覆盖淘汰旧命令后可立即回收相邻空间，最大可分配块基本维持在“堆大小 − 活跃占用”，而不是随运行时间单调下降。

12.3 评审结论（5 项待确认已全部关闭）

原编号待确认项评审结论
① R-01MEM_HEAD_INFO 是否去掉 end_node接受默认方案：去掉 end_node，块头保持 16 B，末尾节点由 g_heap_end − 16 推算
