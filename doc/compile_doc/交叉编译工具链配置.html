OSZ 交叉编译工具链配置说明

从“改脚本适配一台机器”到“设两个环境变量适配任意工具链”

文档版本v1.0（自适应工具链已落地）
更新日期2026-11-24
代码基线main 7e2cf67
适用对象在非 Linux 主机 / 非官方工具链上构建 rv32 目标的人

01结论先行

旧脚本把三件事写死在仓库里：工具链前缀（riscv32-unknown-elf）、工具链目录（tools/toolchain 符号链接指向某个绝对路径）、gcc 版本目录（lib/gcc/.../14.2.0）。任何一条不匹配，配置阶段就失败，而这些都在受版本控制的文件里，换机器就必须改代码。

现在的做法是：仓库只负责“按约定找工具链”，具体路径由使用者用两个变量提供，其余信息（sysroot、libgcc 位置、是否带 C++ 前端）由编译器自己回答。

2 个变量OSZ_CROSS_ROOT / OSZ_CROSS_PREFIX
3 级回退-D 参数 → 环境变量 → tools/toolchain → PATH
0 处硬编码目录结构、gcc 版本、C++ 前端都不再假设
同一产物rv32 ELF，链接脚本与会话常量保持不变

02当前交叉编译架构

本机实际跑通的链路如下：主机是 macOS（arm64），工具链是 xPack 的 riscv-none-elf-gcc 15.2.0，目标 rv32g / ilp32d，产物是 32 位 RISC-V 静态 ELF。

环节本项目取值是否可配置
主机macOS（arm64）；Linux 同样适用—
工具链前缀本机实测 riscv-none-elf（xPack GCC 15.2.0）OSZ_CROSS_PREFIX
工具链根目录本机 /Users/zyzs/tools/riscv/xpack-riscv-none-elf-gcc-15.2.0-1OSZ_CROSS_ROOT
目标架构 / ABIrv32g / ilp32dOSZ_CROSS_ARCH / OSZ_CROSS_ABI
编译特征-ffreestanding -nostdlib -g工具链文件内固定
链接特征-nostdlib -nostartfiles -Wl,--gc-sections -T osz.ld工具链文件内固定
产物build/targets/qemu_virt/target_qemu（ELF32，静态）—
验证命令file / readelf -h / nm（工具链自带 binutils）—
为什么强调“编译器自己回答”：sysroot 与 libgcc 的实际位置由发行包的布局决定，官方 riscv-gnu-toolchain 是 <prefix>/riscv32-unknown-elf/lib，xPack 是 <prefix>/riscv-none-elf/lib，版本号还会随升级变化。用 --print-sysroot 与 -print-file-name=libgcc.a 问编译器，就不会再出现“升一版 gcc 就要改脚本”的情况。

03工具链查找与选择机制

construct/cmake/riscv32_toolchain.cmake 在 project() 之前生效，负责把编译器与一套 binutils 注册给 CMake。

顺序来源说明
1-DOSZ_CROSS_ROOT / -DOSZ_CROSS_PREFIX优先级最高，适合脚本、CI、多工具链并存
2环境变量 OSZ_CROSS_*只在未用 -D 指定时生效，适合“这台机器的默认”
3tools/toolchain支持 <root>/bin 与 <root>/<prefix>/bin 两种布局；目录或符号链接均可，已 git-ignore
4系统 PATH最后的兜底，适合把工具链 bin 直接加进 PATH 的人

前缀同样是“给定优先、否则按发行包命名依次尝试”：用户指定的值 → riscv32-unknown-elf（官方 riscv-gnu-toolchain）→ riscv-none-elf（xPack）→ riscv64-unknown-elf（用 -march=rv32* 也能出 rv32 目标）。命中即停止。

04配置参数

变量类型默认作用
OSZ_CROSS_ROOT路径空工具链根目录（其下有 bin/）。空则查 tools/toolchain 与 PATH
OSZ_CROSS_PREFIX字符串空如 riscv-none-elf；空则自动探测
OSZ_CROSS_ARCH字符串rv32g传给 -march
OSZ_CROSS_ABI字符串ilp32d传给 -mabi
OSZ_REQUIRE_CXX布尔OFFTRUE 时工具链必须带 cc1plus，否则配置阶段直接失败
# 方式一：环境变量（换机器只改这两行）
export OSZ_CROSS_ROOT=/opt/xpack-riscv-none-elf-gcc-15.2.0-1
export OSZ_CROSS_PREFIX=riscv-none-elf
./construct/build_cmake.sh target_qemu

# 方式二：一次性命令行参数
cmake -S . -B build -DOSZ_CROSS_ROOT=$HOME/tools/xpack-gcc -DOSZ_CROSS_PREFIX=riscv-none-elf
cmake --build build -j

# 方式三：什么都不设，把工具链放进仓库 tools/toolchain（该目录已被 git-ignore）
ln -s $HOME/tools/xpack-gcc tools/toolchain
./construct/build_cmake.sh target_qemu

05C++ 前端缺失时的处理

很多 RISC-V 发行包只装 C 前端，不带 cc1plus，而旧脚本用 project(OSZ LANGUAGES C CXX ASM) 强制探测 C++ 编译器，结果“工具链能用但配置过不去”。

现在的规则：

  1. project() 只声明 C ASM；
  2. 工具链文件执行 <prefix>-g++ -print-prog-name=cc1plus，能解析成存在的绝对路径才置 OSZ_CROSS_HAS_CXX=TRUE；
  3. 为真才 enable_language(CXX)，否则跳过。内核没有 C++ 翻译单元，构建结果不变；
  4. CI 或需要完整工具链的人加 -DOSZ_REQUIRE_CXX=TRUE，缺前端时在配置阶段就看到明确错误，而不是编译到一半才失败。
不要把“跳过 CXX”理解成可以随便编译 C++：若将来真的引入 .cpp 翻译单元，缺 C++ 前端的工具链会在编译该文件时报错。OSZ_REQUIRE_CXX 就是给这种场景预留的显式闸门。

06目录与版本控制约定

路径是否纳入 git说明
construct/cmake/riscv32_toolchain.cmake是只包含查找逻辑与编译/链接参数，不含任何绝对路径
tools/toolchain否（已加入 .gitignore）本机的工具链目录或符号链接，属于环境而非代码
build/ 及各 build-* 目录否构建产物，含 targets/qemu_virt/target_qemu

07旧 Makefile 路径（仍然保留）

construct/build.sh 走的是另一条老链路，不改也不影响 CMake 构建：

  1. 工具链压缩包放到 /home/<user>/tools/toolchains，例如 riscv32-unknown-elf.tar.gz；
  2. 把 construct/script/env.sh 的 compiler_name 改成对应前缀；
  3. 脚本检查该路径下是否存在 ${compiler_name}.tar.gz，缺失则报 Error: not fount ...tar.gz；
  4. 解压后导出 CROSS_COMPILER_PATH、QEMU_PATH、COMM_MK、CFG_MK、MODULE_MK、OUTPUT_PATH。
迁移建议：新机器直接用 build_cmake.sh；env.sh 一块维持现状，避免两套配置互相打架。若要把老路径也做成自适应，参照第 03 节的查找顺序改造 env.sh 即可，但需同步 build_make.sh 的验证。

08排错手册

现象根因处理
cannot execute 'cc1plus'工具链缺 C++ 前端，但 CXX 被强制启用本版已自动跳过 CXX；若被 OSZ_REQUIRE_CXX=TRUE 拦住则换完整工具链
链接阶段报 cannot find qc / libxxx.a工具注册用了共享的 find_program 缓存变量，ar 被误认成 gcc已修：每个工具独立变量 OSZ_TOOL_<tool>
arch_adapter.h: No such file or directorykernel/base/mem 未声明对 arch_riscv 的依赖（只在交叉构建暴露，宿主单测走 OSZ_TESTING 分支）已修：PRIVATE_DEPENDENCIES arch_riscv
tools/toolchain 指向不存在的 /home/xxx旧提交把符号链接纳入了版本控制本版已从 git 移除并忽略；本机重新指向自己的工具链即可
配置报“找不到 RISC-V 交叉工具链”四个来源都没命中按提示设置 OSZ_CROSS_ROOT/OSZ_CROSS_PREFIX，或把 <prefix>-gcc 放进 PATH
ELF 产出但地址不对链接脚本选择错误确认 -T construct/osz.ld，并用 readelf -h 核对 entry 与段地址

10命令速查

# 构建
cmake -S . -B build -DOSZ_CROSS_ROOT=<root> -DOSZ_CROSS_PREFIX=<prefix>
cmake --build build -j8

# 校验产物
file build/targets/qemu_virt/target_qemu
<prefix>-readelf -h build/targets/qemu_virt/target_qemu
<prefix>-nm  build/targets/qemu_virt/target_qemu | grep inner_mem

# 换工具链 / 换机器
export OSZ_CROSS_ROOT=<new root>
export OSZ_CROSS_PREFIX=<new prefix>
rm -rf build            # 换编译器后必须清缓存，否则 CMAKE_C_COMPILER 沿用旧值
换工具链必须清构建目录：编译器路径写在 CMakeCache.txt 里，只改环境变量重新 configure 不会替换它。
